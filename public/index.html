Glossary
3DS ServerSoftware run by the merchant or its provider. It starts the authentication and talks to the card network.
Directory Server (DS)The card network's switch (Visa, Mastercard and others). It finds the right issuer for a card and passes messages on.
ACSAccess Control Server, the issuer's system. It judges the risk and runs the challenge.
Issuer / acquirerThe issuer is the cardholder's bank. The acquirer is the merchant's bank, which sends the payment for authorisation.
AReq / AResAuthentication Request and Response. The 3DS Server asks the issuer to authenticate, the issuer answers with a transStatus.
CReq / CResChallenge Request and Response, exchanged between the customer's browser and the ACS during a challenge.
RReq / RResResults Request and Response. After a challenge, the ACS reports the final outcome to the 3DS Server. This is the message to trust.
Frictionless / challengeFrictionless: the issuer approves in the background. Challenge: the customer must prove who they are, for example with a code.
transStatusY authenticated. N denied. U could not be performed. A attempt recorded. C challenge required. R rejected by the issuer.
ECITells the networks how the cardholder was authenticated. Visa: 05 authenticated, 06 attempted, 07 not authenticated. Mastercard: 02, 01, 00.
CAVV / AAVThe cryptographic proof of authentication (Visa calls it CAVV, Mastercard AAV). It travels with the authorisation request.
Liability shiftWhen a payment is properly authenticated, responsibility for "the cardholder did not make this purchase" fraud chargebacks moves from the merchant to the issuer.

Failure script

Make the gateway misbehave on a schedule, the way production does. Decline every third payment, return a 503, answer slowly, or send webhooks twice, late, never, or with a bad signature. Rules run in order and the first match wins. Included in Pro and in the free trial.

How rules work

Each rule has when (all conditions must match; leave it out to match every payment) and then.

when.nthOnly the Nth payment since you saved the script (1, 2, 3...).
when.everyEvery Nth payment.
when.amount_gte / amount_lteAmount at or above or at or below a value.
when.currency / method / transaction_typeMatch one currency, method or type.
when.probabilityA chance from 0 to 1, for random failures.
then.outcomeapprove, decline, nsf, expired, timeout, 3ds, 3ds_Y, 3ds_N, 3ds_A, 3ds_U, 3ds_R. Overrides the test card.
then.latency_msWait up to 10,000 ms before answering.
then.http_errorAnswer 500, 502 or 503 and create no payment. Retry with the same request_id.
then.webhookduplicate (1 to 3 extra copies), delay_ms (up to 60,000), drop, bad_signature.

Payments changed by a rule show script_rule, the rule's number. Rejected-by-script requests do not count against your monthly limit.

Verify the signature (Node.js)

const crypto = require("crypto");
function verify(rawBody, header, secret) {
  const [t, v1] = header.split(",").map((p) => p.split("=")[1]);
  const expected = crypto.createHmac("sha256", secret)
    .update(`${t}.${rawBody}`).digest("hex");
  const fresh = Math.abs(Date.now() / 1000 - t) < 300;
  return fresh && expected.length === v1.length &&
    crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(v1));
}
// header: req.headers["x-dryrun-signature"], body: the raw request text

API quick start

Create a key above, then call the API from your own code. Every request needs the header Authorization: Bearer sk_test_.... Reusing a request_id is rejected, like on a real gateway.

# create a payment
curl -X POST /v1/payments \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"request_id":"order-1001","method":"card","transaction_type":"purchase",
       "amount":49.90,"currency":"EUR","card_number":"4111111111111111"}'

# refund part of it
curl -X POST /v1/payments \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"request_id":"refund-1","method":"card","transaction_type":"refund",
       "amount":10,"parent_transaction_id":"tx_..."}'

# complete a 3D Secure challenge
curl -X POST /v1/payments/tx_.../3ds \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"result":"approve"}'

Methods: card, paypal, ideal, sepa. Transaction types: purchase or debit, authorization, capture-authorization, refund, void. Currencies: EUR, USD, GBP. Optional scenario: auto, approve, decline, timeout, 3ds.
